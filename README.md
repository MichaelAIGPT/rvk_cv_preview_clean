# RVK Safety CV — Промышленная система видеоаналитики ТБ и мониторинга СИЗ

**ООО «РВК.Цифровые решения» (Группа компаний «Росводоканал»)**  
*Комплексная программная платформа интеллектуального видеоконтроля охраны труда и промышленной безопасности.*

---

## 📌 О проекте

**RVK Safety CV** — отечественная система компьютерного зрения корпоративного уровня, разработанная для непрерывного автоматического контроля соблюдения правил охраны труда (ОТ и ТБ) на технологических объектах водоснабжения и водоотведения:
- Цеха механического обезвоживания осадка (ЦМОО);
- Насосные станции первого и второго подъемов, машинные залы ГНС;
- Осадкоуплотнители, первичные и вторичные радиальные отстойники;
- Транспортные галереи кека и конвейерные линии;
- Гаражи спецтехники и боксы аварийно-восстановительных машин (АВМ).

Система работает в режиме 24/7, обрабатывает RTSP-видеопотоки высокого разрешения (Full HD / 4K), детектирует персонал, определяет наличие средств индивидуальной защиты (СИЗ), контролирует нахождение в опасных зонах технологического оборудования и формирует юридически значимый реестр инцидентов с расследованием по методике **CAPA (5 Почему)**.

## 🏗️ Архитектура системы: Трехстадийный каскад SOTA V3

В отличие от устаревших одностадийных сетей (детекторов «все-в-одном», путающих каски с круглыми трубами и вентилями), платформа RVK Safety CV построена на модульном трехстадийном каскаде:

```
                  ┌──────────────────────────────────────────────┐
                  │   Панорамный видеопоток цеха (1920×1080)     │
                  └──────────────────────┬───────────────────────┘
                                         │
                                         ▼
                 ┌────────────────────────────────────────────────┐
                 │   СТАДИЯ 1: Детектор человека (YOLOv8)         │
                 │   • Безупречная локализация силуэтов в кадре   │
                 │   • Обучен на 1.5+ млн изображений людей       │
                 └───────────────────────┬────────────────────────┘
                                         │
                                         ▼
                 ┌────────────────────────────────────────────────┐
                 │   СТАДИЯ 2: Оценка поз (YOLOv8-Pose)           │
                 │   • Определение анатомического скелета         │
                 │   • Ключевые точки: голова, уши, плечи, торс   │
                 │   • Точная изоляция областей СИЗ в наклоне     │
                 └───────────────────────┬────────────────────────┘
                                         │
                                         ▼
                 ┌────────────────────────────────────────────────┐
                 │   СТАДИЯ 3: Классификатор СИЗ (EfficientNet-B0)│
                 │   • ⛑️ Каски: F1 = 0.985                        │
                 │   • 🦺 Жилеты: F1 = 1.000                       │
                 │   • 🚫 Подавление ложных тревог оборудования   │
                 │     (Hard Negative Mining: трубы, задвижки)    │
                 └────────────────────────────────────────────────┘
```

### Преимущества каскадной схемы:
1. **Разделение ответственности:** Базовый детектор людей не ломается при дообучении на спецодежду.
2. **Быстрое дообучение (Active Learning):** Дообучение верхнего классификатора СИЗ на новых образцах цеха занимает всего **2–3 минуты на GPU**.
3. **Отсутствие ложных тревог:** Модуль поз вырезает строго область головы и плеч, отсекая металлоконструкции на заднем плане.
4. **Гибкость развертывания:**
   - **GPU SOTA (EfficientNet-B0):** Максимальная точность для серверов видеонаблюдения с дискретными видеокартами (RTX 3060/4070/A4000). Задержка инференса: **9.8 мс**.
   - **CPU Edge (MobileNetV3):** Оптимизированный легковесный контур для работы на стандартных офисных процессорах (Intel Core / Xeon Silver) без GPU. Задержка инференса: **8.2 мс**.

| Критерий | Базовая модель подрядчика (YOLOv8n Single-Stage) | RVK Safety CV SOTA V3 (Трехстадийный каскад) |
| :--- | :--- | :--- |
| **Архитектура** | Одностадийная (bbox всего тела) | Трехстадийный каскад (YOLOv8 + Pose + EfficientNet) |

| **F1-Score по каскам** | 0.68 | **0.985** |
| **F1-Score по жилетам** | 0.74 | **1.000** |
| **Реакция на трубы и насосы** | Постоянные ложные детекции («голова в каске») | Полное подавление (84+ эталона Hard Negatives) |
| **Контроль опасных зон** | Отсутствует | Интерактивный полигональный редактор зон опасности |
| **Поведение людей** | Только СИЗ | Детекция курения, разговоров по смартфону в зоне |
| **Сегментация силуэта** | Отсутствует | Полигональная маска силуэта (YOLOv8-Seg) |
| **Детекция пожара/дыма** | Отсутствует | Специализированный детектор открытого огня и задымления |
| **Контур Active Learning** | Отсутствует (статичные веса) | Встроенный банк кропов, FastTagger и фоновое MLOps-дообучение |

## 🛡️ Логика видеопотока vs Юридический журнал инцидентов

Система четко разграничивает работу в реальном времени и фиксацию нарушений:
- **На видеопотоке (HUD 25 FPS):** Каждый человек непрерывно сопровождается трекером с постоянным ID. Индикация `🪖 Каска` / `🧢 БЕЗ КАСКИ` горит над фигурой на **каждом кадре**.
- **В журнале инцидентов ТБ:** Для предотвращения информационного спама диспетчера работают промышленные фильтры:
  - **Фильтр дребезга (Debounce 3+ кадра):** Единичные повороты головы или смазывание при беге отфильтровываются. Требуется устойчивая фиксация.
  - **Кулдаун дедупликации (15–30 сек):** Если рабочий без каски идет по цеху 10 секунд (250 кадров), система регистрирует **ровно один инцидент** в журнале с привязкой к его треку, а не создает 250 одинаковых карточек.

## 📋 Функциональные возможности веб-интерфейса

Веб-приложение доступно в браузере по адресу `http://localhost:8088/`:

1. **Операционный центр (`switchTab('operations')`):**
   - Интерактивный Full HD видеоплеер с аппаратным зумированием (колесико мыши от 50% до 300%) и режимом панорамирования (Pan / Drag).
   - Быстрый переход в режим театра («⛶ На весь экран»).
   - Управление скоростью воспроизведения (0.5x, 1x, 2x, 4x), пошаговая перемотка (⏮️ / ⏭️).
   - Мульти-камерная сетка с живыми превью технологических зон (Камеры 1–5).
2. **Модули контроля ТБ (Toolbar):**
   - `⛑️ Каски` — контроль защитных шлемов;
   - `🦺 Жилеты` — контроль сигнальной спецодежды со световозвращающими полосами;
   - `🚬 Курение` — обнаружение тлеющих сигарет и характерного жеста поднесения руки ко рту;
   - `📱 Смартфон` — контроль использования мобильных устройств в зоне движущихся механизмов;
   - `⚠️ Опасные зоны` — подсветка полигонов оборудования и контроль опасного сближения;
   - `🧩 Маска силуэта` — включение YOLOv8-Seg для отсечения сложного фона;
   - `⚡ Сравнение A/B` — параллельный бенчмарк слоев (🟩 Наша SOTA V3 vs 🟧 База Заказчика).
3. **Банк кропов и Золотая выборка (`/dataset`):**
   - Каталог проверенных силуэтов с фильтрацией: *Все*, *🔥 Новые из сессии*, *В каске*, *Без каски*, *Оборудование / Hard Negatives*, *Склейки*.
   - Сортировка: *Сначала новые*, *Сначала старые*, *По номеру трека*.
   - Инструмент экспресс-разметки **FastTagger** (`/tagger`) с горячими клавишами.
4. **Центр Active Learning Hub (`/api/learning`):**
   - Учет накопленных образцов для дообучения.
   - Выбор модели (Флагман SOTA V3, MobileNetV3 Edge, База Заказчика).
   - Кнопка запуска фонового дообучения на GPU (`🚀 Запустить фоновое дообучение`).
   - Кнопка экспорта в YOLO-формат (`📥 Экспорт в YOLO`).
5. **Журнал событий и CAPA-расследование (5 Почему):**
   - Реестр зафиксированных нарушений с фильтрацией по статусам (*Новый*, *Подтверждено*, *Ложное*).
   - Кнопка **`▶ В плеер`** — мгновенный переход к точному кадру инцидента.
   - Карточка расследования инцидента по стандарту 5 Whys с назначением корректирующих мер (CAPA), ответственного лица и дедлайна.
   - Экспорт отчетов для руководства в форматах **Excel XLSX**, **CSV (1C:ERP)** и **SCADA OPC UA Telemetry**.
6. **Ролевая модель доступа (RBAC):**
   - **Администратор** (полный доступ, конфигурация камер, калибровка зон);
   - **Инженер ТБ / ML** (доступ к Active Learning, переключению весов, бенчмаркам);
   - **Оператор / Диспетчер** (просмотр потоков, триаж тревог, управление плеером);
   - **Специалист ОТ** (ведение CAPA-расследований, аналитика причин);
   - **Руководитель** (сводка KPI, динамика нарушений, выгрузка сводных отчетов).

## 💻 Системные требования

### Рекомендуемая конфигурация (GPU):
- **ОС:** Windows 10/11 x64 или Linux (Ubuntu 22.04 LTS / РЕД ОС / Astra Linux);
- **Процессор:** Intel Core i5/i7 (от 10-го поколения) или AMD Ryzen 5/7;
- **Оперативная память:** 16 ГБ RAM;
- **Видеокарта:** NVIDIA GeForce RTX 3060 / 4060 / 4070 / RTX A2000 (от 6 ГБ VRAM, CUDA 11.8 / 12.x);

- **Процессор:** Intel Core i5 / Xeon Silver с поддержкой AVX2;
- **Оперативная память:** 8 ГБ RAM;
- **Видеокарта:** Не требуется (инференс на MobileNetV3 / OpenVINO).

## 📡 Спецификация REST API

Сервер предоставляет интерактивную документацию Swagger OpenAPI:  
👉 **`http://localhost:8088/docs`**

### Основные эндпоинты:
- `GET /api/stream/live` — Живой MJPEG-видеопоток с наложенной графикой детекций.
- `GET /api/stream/raw_live` — Чистый видеопоток без графических аннотаций.
- `GET /api/stream/state` — Телеметрия текущего кадра (FPS, задержка мс, обнаруженные сотрудники, координаты bbox).
- `GET /api/stream/snapshot?cam=1..5` — Получение панорамного стоп-кадра высокого разрешения с камер 1–5.
- `POST /api/stream/seek` — Перемотка видеопотока на заданный номер кадра (`{"frame_idx": 42}`).
- `POST /api/stream/playlist` — Переключение источника/смены (`golden`, `smoke_fire_test`, `all_5000` и др.).
- `GET /api/incidents` — Реестр зарегистрированных нарушений ТБ.
- `POST /api/incidents/{id}/verify` — Верификация инцидента оператором (`verified` / `false_alarm`).
- `POST /api/incidents/{id}/hse` — Обновление карточки расследования 5 Whys и мер CAPA.
- `GET /api/incidents/export/director?format=xlsx` — Выгрузка аудиторского отчета в Excel XLSX.
- `GET /api/incidents/export/scada` — Выгрузка телеметрии реального времени для АСУ ТП / SCADA (OPC UA).
- `GET /api/learning/samples` — Получение манифеста размеченных образцов и статистики классов.
- `POST /api/learning/train` — Запуск фонового дообучения модели на GPU (`{"epochs": 15, "batch": 8}`).
- `GET /api/learning/runs` — История прогонов тестирования и динамика прироста точности.
- `POST /api/learning/runs/record` — Фиксация результатов текущего тестового прогона.
